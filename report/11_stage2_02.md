## 逐条复核

### 1. E820 的 `jnc`→`jne` 已修复

`boot/stage2.s:177` 现在是：
```asm
    cmp eax, 0x534d4150
    jne .done
```
反汇编确认：
```
000009F9  663D50414D53      cmp eax,0x534d4150
000009FF  7524              jnz 0xa25
```
机器码是 `0x75`（JNZ/JNE），不再是之前的 `0x73`（JNC）。E820 现在只有在 EAX 确实不等于 `'SMAP'` 时才会放弃转入回退分支，逻辑和意图一致。**判定：修复确认。**

### 2. E801 回退路径已经重写，16MB 以上的内存不再丢失

`boot/stage2.s:201-276` 整段 `.fallback` 被重写了，反汇编逐条核对如下：
- 先按 AX/BX 是否都为 0 来决定要不要改用 CX/DX（`test ax,ax`/`test bx,bx` 两次判断，都不成立才 `mov ax,cx; mov bx,dx`）——符合"部分 BIOS 只把结果写进 CX/DX"的标准约定。
- 条目 I（0~0x9FC00，恒写）、条目 II（1MB 起、长度 `ax<<10`，仅当 `ax≠0`）、条目 III（16MB 起、长度 `bx<<16`，仅当 `bx≠0`）三段分支的机器码（`test`/`jz`/`shl`/`mov dword`）都符合源码语义，`di` 每写一条正确推进 0x14（20 字节）。
- 条目数量不再硬编码成 2，而是用 `(di - MMAP_ENTRIES) / 20` 现算（`sub ax,0x8010` 接 `div cx`(cx=0x14)），无论最终写了 1/2/3 条都能算对。
- `ax`/`bx` 都为 0 时（`.none` 分支）正确判定"真的没有可用内存"，不会伪造出一条条目。

用同样的方式人工过了一遍边界情况（`ax=0,bx≠0` 只写条目 I+III；`ax≠0,bx=0` 只写条目 I+II；两者都非 0 写全三条），指令序列都对得上。**判定：修复确认，且比之前的实现更严谨（条目数改成动态计算，不再是硬编码假设）。**

### 3. `$(ELF)` 缺少 `| $(BIN_DIR)` 已修复

`makefile:79` 现在是：
```makefile
$(ELF): $(OBJS) link.ld | $(BIN_DIR)
```
用上次能复现问题的原始命令重新验证：
```
$ rm -rf bin
$ make bin/stage2.bin bin/mbr.bin
nasm -f elf32 -DPART_LBA=2048 boot/stage2.s -o boot/stage2.o

nasm -f bin -DIMG_SECTORS=131040 -DPART_LBA=2048 boot/mbr.s -o bin/mbr.bin
```
`mkdir -p bin` 现在正确地排在 `ld` 之前执行，不再报 `cannot open output file`。另外补跑了一次干净的 `make -j8 all`，全程无错误。**判定：修复确认。**
