# 验收报告 · 第10章 · boot/mbr.s

**对照规范:** SPEC/10-boot-mbr.md
**审查文件:** boot/mbr.s（当前 112 行，规范文档描述的是 v1 版本 152 行，属预期内的重写差异）
**结论:** ACCEPT（未发现功能性 bug）

## 验证方法

- 通读源码，逐条核对 BIOS 调用约定（INT 13h AH=00h/41h/42h/02h）的寄存器用法。
- 用 makefile 实际参数重新汇编：`nasm -f bin -DIMG_SECTORS=131040 -DPART_LBA=2048 boot/mbr.s`，汇编无警告无错误，输出恰好 512 字节。
- 用 `ndisasm` 反汇编已构建的 mbr.bin，逐指令核对与源码语义一致。
- 用 `xxd` 检查分区表字节与引导签名的实际内容。
- 用 Python 核算分区表里的 LBA 起始/扇区数字段，与 makefile 的 `IMG_SECTORS=131040` / `PART_LBA=2048` 比对。
- 核对 `link.ld` 中 `STUB_SECTS=8` 与 mbr.s 里硬编码的 `8`（DAP 的 sects 字段、CHS 分支的 `al=8`）是否一致。

## 检查结果

1. **DAP 结构正确。** `dap` 的 16 字节布局（size=0x10, resv=0, sects=8, offset=0x900, segment=0, lba=1）完全符合 INT 13h AH=42h 的标准格式，字段大小加总正好等于声明的 0x10。
2. **LBA→CHS 回退逻辑正确。** AH=41h 扩展检测（BX 回读 0xAA55、CX bit0 判断）、AH=42h 失败后落空到 `.use_chs` 的顺序执行、CHS 分支的 C/H/S 取值（cylinder=0, sector=2, head=0，对应 LBA=1）均核对无误，且两条路径读取的扇区数（8）与目标缓冲区（0000:0900）完全一致。
3. **跳转前状态正确。** 无论走 LBA 还是 CHS 分支，最终在 `.load_ok` 处都会重新从 `[boot_drv]` 加载 `dl` 后再 `jmp 0x0:0x900`，`ss/ds/es` 全程保持 init 阶段清零的状态，符合规范 Public interface 里对 Exit 状态的要求。
4. **分区表字节核算正确。** 实际汇编产物在 0x1BE 处的 16 字节为 `80 FE FF FF 0C FE FF FF 00 08 00 00 E0 F7 01 00`：LBA 起始 = 0x00000800 = 2048（=PART_LBA），扇区数 = 0x0001F7E0 = 128992（= IMG_SECTORS(131040) − PART_LBA(2048)），CHS 哨兵值 `FE FF FF` 符合"CHS 不可表示"惯例，type=0x0C（FAT32 LBA）正确。
5. **跨文件常量一致。** `link.ld` 的 `STUB_SECTS=8` 与 mbr.s 里两处硬编码的 `8`（DAP sects、CHS 分支 al）数值一致，未发现不一致导致的读取截断风险。
6. **引导签名与布局正确。** 二进制恰为 512 字节，0x1FE-0x1FF 处为 `55 AA`，分区表前的 `times 0x1be-($-$$) db 0` 与分区表后的填充计算均无溢出。

## 备注（非缺陷，仅记录）

以下几点 SPEC/10-boot-mbr.md 本身已经点名是"待重写时考虑"的设计取舍，不属于本次代码的新增问题，故不计入 bug，仅在此存档以便后续追踪：

- `STAGE2_SECTS`/`STUB_SECTS`/`PART_LBA`/`IMG_SECTORS` 依然分散硬编码在 mbr.s / link.ld / makefile 三处，无单一事实来源，构建期无交叉校验。
- CHS 回退分支未查询 BIOS 磁盘几何（INT 13h AH=08h）即假设磁道 ≥9 扇区，与 v1 行为一致，非本次引入。
- 单磁盘假设（`boot_drv` 默认 0x80，且从不校验 `dl` 的合理性）与 v1 相同，规范文档已将其列为"待决问题"，非本次代码新引入的错误。

## 判定

未发现导致 boot/mbr.s 行为偏离 SPEC/10-boot-mbr.md 所述接口/依赖约定的 bug。本章验收通过。
