# 02 — 横切决策

AHCI、网卡、EXE/DLL、任务、GUI 之所以"互相牵扯"，是因为它们共用几个底层前提。
这些前提只要定一次，各模块就能分开做。这里每条决策都写了**理由**和**代价**，
推翻某条之前先看它影响了谁。

状态标记：**〔定〕** 已拍板 / **〔荐〕** 建议，等你确认 / **〔待〕** 未决。

---

## D1 段模型：全平坦 〔荐〕

所有代码段、数据段 base = 0，limit = 4GB。任务之间**不靠段隔离**，只靠 TSS 保存各自的寄存器。

**理由**

- ABI 表里存的是**绝对地址的函数指针**（`LW_CALL` 直接把 slot 当函数指针调用）。如果某个任务的段 base ≠ 0，它拿到的指针就全错了，除非每次调用都改成远调用。
- 无分页时**线性地址 = 物理地址**。平坦段下，C 指针的值就是可以直接写进 AHCI/网卡描述符的 DMA 地址。段 base ≠ 0 时每个 DMA 地址都要手动加 base，漏一处就是一次内存踩踏。
- DLL 要被多个任务共享。平坦下同一份代码对所有任务地址相同；分段下做不到。

**代价**

- **没有内存保护**。一个任务写飞会踩坏别人（前面画曲线越界就是这种情况）。
- EXE 不能固定链接到同一个地址，**必须做加载时重定位**（见 [40](40-lwp-exe.md)）。

**以后想要保护怎么办**：可以给 APP 任务的段设 limit（不改 base），能挡住一部分越界。真要隔离就得上分页，那是另一个项目了。

## D2 系统层：resman 是内核，ABI 是 HAL 〔荐〕

```
APP      MONITOR / 以后的 EXE           （APP 编译选项，可用 x87）
         ─────────── 查表调用 ───────────
KERNEL   RESMAN.BIN  0x180000  身份 'LWRM'       （KERN 编译选项）
           拥有：GDT、IDT、PIC、PIT、内存、任务、EXE/DLL 加载器、设备表
         ─────────── 查表调用 ───────────
HAL      ABI.BIN     0x100000  身份 'LWAB'       （KERN 编译选项）
           拥有：端口 IO、控制台、键盘、PCI 配置空间、各设备驱动
```

- **ABI 不分配内存**。驱动需要的 DMA 缓冲由调用方（resman）分配后传进来。这样 ABI 永远不依赖 resman，层次不会倒挂。
- **ABI 不拥有中断**。它只提供"轮询一次"的函数，由 resman 决定是在主循环里调还是在 ISR 里调（见 D4）。
- **IDT 从 monitor 移到 resman**。monitor 作为调试器，通过 resman 的"挂接向量"接口拿单步、断点这些异常。
- resman 的源码建议从 `app/resman/` 挪到 `lib/resman/`：它是 KERN 层，要用 `CFLAGS_KERN`，放在 `app/` 下会用错编译选项。根目录下那个空的 `resman/` 删掉。

resman 用和 ABI 一样的机制：固定地址、映像开头一张 slot 表、只追加不改号。
BOOT.INI 增加一行 `LOAD "RESMAN.BIN" TO 180000H`，并先于 monitor ATTACH。

slot 0 的 `LWAB` 表示"可加载映像"（MONITOR.BIN 也用它），不表示"这是 ABI"。
各映像的身份另放在一个 slot 里，loader 需要相应修改，详见 [50](50-resman-memory.md)。

## D3 驱动怎么接入 ABI：一个绑定入口 + 设备对象 〔荐〕

每加一个驱动就加几个 slot 不可持续（slot 永久占号）。改成：

- ABI 内部有一张**驱动表**（每个驱动一项：匹配的 vendor/device 或 class、probe 函数）。
- ABI 只导出**一个** slot：`lw_drv_bind(const PCI_DEV *d, PVOID dma, DWORD dma_size)`。
  它在内部驱动表里找匹配项并调用 probe，成功就返回一个**设备对象**指针，没有匹配就返回 NULL。
- 设备对象是带版本号的函数表（C 结构体），按设备类别区分：`BLKDEV`（块设备）、`NETDEV`（网卡）。
- resman 负责扫 PCI，对每个功能调一次 `lw_drv_bind`，把得到的设备对象记在自己的设备表里。

好处是：新增网卡型号只需在 ABI 内部的驱动表里加一项，ABI 表不用动，调用方也不用重新编译。

设备对象结构体的规则和 slot 一样：**字段只追加，结构体开头放 `version` 和 `size`**。

## D4 轮询优先，中断后加 〔荐〕

- 现在所有设备都是轮询，第一版驱动也全部轮询。
- 每个设备对象都有一个 `poll()` 函数，做"检查硬件状态、处理完成的请求"这件事。
- 中断上线后，ISR 只做"确认中断 + 调 `poll()`"。**驱动代码不用改**。
- 中断在任务切换阶段（[51](51-tasks.md)）统一上线：重映射 PIC 到 0x20–0x2F，PIT 当时钟。

理由：中断会同时牵动 IDT 归属、PIC、重入问题，拖到一处一起解决，比每个驱动各自处理一遍省事。

## D5 重入与锁 〔荐〕

单 CPU，所以"锁" = 关中断。

- **任务切换上线之前**：什么都不用做。
- **上线之后**：ABI 里凡是有共享状态的地方都要用 `irq_save()` / `irq_restore()` 包起来（保存 EFLAGS.IF，cli，恢复）。典型位置：
  - PCI 的 CF8/CFC 两步访问
  - 控制台光标和显存
  - 键盘缓冲
  - 驱动的描述符环
- BIOS 跳板（`tramp_call`）会切回实模式，**只允许在单任务阶段调用**（启动时设置显示模式）。任务开始后调用应当直接返回错误。

## D6 FPU 〔定〕

- KERN 层（ABI、resman、loader）不碰浮点，这条已经由 `CFLAGS_KERN` 强制执行。
- APP 层可以用 x87。任务切换后用**惰性保存**：硬件任务切换会自动置 CR0.TS，APP 第一次碰 FPU 时触发 #NM（向量 7），resman 在那里 `clts` + `fsave` 旧任务 / `frstor` 新任务。详见 [51](51-tasks.md)。

---

## D7 可执行映像两种格式并存 〔荐〕

| 格式 | 头 | 地址 | 用于 |
|---|---|---|---|
| 固定映像 | LWAB 表头（slot 0x00–0x04） | 链接时写死 | ABI.BIN、RESMAN.BIN、MONITOR.BIN |
| LWP | `tools/mkexe` 定义的头 | 加载时重定位 | 以后所有 EXE 和 DLL |

固定映像由 LOADER.BIN 在启动时放好；LWP 由 resman 在运行时加载。
monitor 以后可以改成 LWP，但不急。

## D8 slot 号段规划 〔荐〕

提前划好号段，避免以后插不进去。

**ABI（LWAB）**

| 范围 | 用途 |
|---|---|
| 0x00–0x0F | 映像头 |
| 0x10–0x1F | 控制台 |
| 0x20–0x2F | 端口 IO、键盘、显示模式、FPU |
| 0x30–0x3F | 启动信息（fb 等） |
| 0x40–0x47 | PCI 配置空间 |
| 0x48–0x4F | 驱动绑定（`lw_drv_bind` 等） |
| 0x50–0x5F | 鼠标、定时器等其他原语 |
| 0x60–0x7E | 预留 |
| 0x7F | 保留入口 |

**resman（LWRM）**

| 范围 | 用途 |
|---|---|
| 0x00–0x0F | 映像头（和 LWAB 同构） |
| 0x10–0x1F | 内存：alloc / free / 查询 |
| 0x20–0x2F | 中断：挂接向量、屏蔽 IRQ |
| 0x30–0x3F | 任务：创建、退出、yield、sleep |
| 0x40–0x4F | 加载器：load_exe、load_dll、get_proc |
| 0x50–0x5F | 设备表：按类别取设备对象 |
| 0x60–0x6F | 文件系统（放 resman 还是单独一层见 [22](22-blockdev-fs.md) 的待决问题） |
