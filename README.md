# LWOS

**项目重心是手写内核与程序代码，以及操作系统开发中的编程实践。**

内核与程序实现由人类手工编写；项目描述文件、文档（包括本 README）、宣传文案与宣传方式由 AI 生成。手写实现的声明适用于内核与程序代码，文档和宣传内容则在此明确标注其 AI 来源。文档中的设计与规划仍需对照实际代码确认。

一个以手写内核、底层编程和独立程序开发为重心的业余操作系统，外观和操作感受受到 IBM-PC 启发。LWOS 希望为工具、编辑器、实验程序等提供运行环境，并逐步形成开放的软件生态。CNC（计算机数控）是应用方向之一，独立程序和社区软件无需与 CNC 有关。
注意：LWOS在风格上类似IBM-PC，但是不依赖BIOS。固件支持（自定义BIOS、IBM兼容机）属于另一个独立项目，不是本项目范围内的。

> **状态:** LWOS在早期阶段正在积极重构。仓库正在从零开始重建和标准化，因此API、目录结构可能随时变更，不会通知，磁盘结构是FAT32+自制LOADER。

## 目前可用的功能

- **MBR** — 用于引导系统盘和分区表。
- **FAT32 (read-only)** — 简化版FAT32读取实现在loader里，以后会写高级的多级目录+读写。
- **镜像制作** — 使用 `dosfstools` 的 `mkfs.fat` 和 `mtools` 的 `mcopy`，支持递归目录；安装这两个工具包后运行 `make`。FAT32 每扇区固定 512 字节、每簇 1 扇区。`resources/` 中的文件打包到镜像的 `/RES/`。原 `tools/mkfat` 保留作实验代码。

其他内容（shell、实用工具等）还在规划中，没全实现。

## 正在规划的

- `MONITOR.BIN` — 仿照MS-DOS `DEBUG.COM`但是包含更多ABI的一个调试器
- `EDIT.EXE` — 仿照MS-DOS `EDIT.COM`的文本编辑器
- 关于设计、内存布局的存档

## 开源、二次创作与软件生态

LWOS 重视手工编程，也欢迎大家在许可证允许的范围内修改、分发和二次创作。长期目标是形成一个开放的软件生态：开发者可以编写自己喜欢的程序、工具和资源，向社区软件源投稿，让其他用户发现、安装和使用。

[lwos.dev](https://lwos.dev/) 将逐步成为文档、软件目录和社区投稿的入口。软件源与包管理机制目前仍在规划中：先建立投稿规则和软件目录，再随着可执行格式、加载器和依赖机制的完善，加入安装、更新及第三方软件源支持。

### 创作来源与 AI 标记

手工编程是 LWOS 的文化，来源透明是社区贡献的原则。官方软件源计划要求每个软件包提供创作来源声明；包含生成式 AI 产出的代码、文档、图片或其他资源时，即使经过人工修改，也应如实记录涉及的部件。

| 来源类别 | 声明范围 | 展示方式 |
|---|---|---|
| 人类编写 | 未采用生成式 AI 产出的代码或资源 | 正常收录，详情注明来源为作者声明 |
| AI 辅助 | 仅用于解释、讨论或审查，未采用生成内容 | 在详情中记录辅助情况 |
| 含 AI 生成内容 | 采用了生成内容，包括人工修改后采用 | 明确显示“含 AI 生成内容”并列出涉及部件 |
| 来源未知 | 历史来源不清楚，无法完整声明 | 明确显示“来源未确认” |

标记按实际涉及的部件记录。例如，人类编写的程序使用了 AI 生成图标，应标记图标的来源；LWOS 自身的描述文件、文档和宣传内容也遵循这一原则，声明为 AI 生成。来源声明不要求填写难以核实的 AI 占比，也不把自动检测结果当作创作来源的证明。

官方软件源的发布流程计划强制检查来源声明，并将其关联到具体版本：源码中保留来源记录，软件包元数据携带声明，软件目录及包详情自动展示对应标记。投稿者不能在官方源中关闭这些标记；后续打包工具和可执行格式也将考虑提供可查询的来源信息。缺少声明的投稿不能进入官方源，故意隐瞒需更正，反复隐瞒可能导致下架或暂停投稿资格。

这些要求属于**官方软件源的收录与发布政策**，不修改本项目的 GPLv3 许可证，也不以进入官方源作为修改或分发 LWOS 的前提。声明与签名可以追溯版本及责任人，但不能独立证明代码是否由人类手写。

### 投稿与质量

软件源计划通过 PR 接收投稿，要求提供源码地址、许可证、维护者、构建方法、兼容的 LWOS ABI 版本及依赖信息。独立软件包应明确自己的许可证；使用或修改本项目代码时，须遵守适用的许可条款。

创作来源与软件质量分别记录。人类编写或 AI 参与都不能代替测试和审查，涉及实际设备控制的组件还需要专门的验证要求。具体投稿流程、元数据格式和审核标准将在软件源落地时进一步制定。

## 仓库结构
    boot/     MBR + STAGE2（实模式，磁盘保留扇区）
    loader/   LOADER.BIN 与 BOOT.INI
    lib/      库；lib/include 为公开头文件（abi.h 等）
      abi/    ABI.BIN，src/ 与 include/（私有头）分开
    app/      运行在 ABI 之上的程序（monitor、test1），各自 src/ 与 include/ 分开
    build/    中间产物（.o/.d），bin/ 为成品
    fsroot/ 用于构建FAT32的暂用目录
    tools/  宿主机侧实用工具
    report/ 评审笔记（review）
    SPEC/   规格书
    spec2/  v2 规格书
    site/   lwos.dev 站点（Astro，独立于 OS 构建，见 site/README.md）

## 构建与运行

要求：

- 有 `make` 的 Unix 类环境
- C 编译器
- [QEMU](https://www.qemu.org/) or [Bochs](https://bochs.sourceforge.io/)

在模拟器中构建并启动：

```sh
make run
```
